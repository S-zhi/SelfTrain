# 交给其他 Agent 的出题模板

复制下面完整的 `text` 代码块，并按本批需求填写开头四项。在下方 Go 示例中，语言字段写 `Go`，版本写在 `go_version`；任意学科都可替换。

```text
语言/学科：Go
主题范围：Go 1.25 常见语法，覆盖变量与常量、数组与切片、映射、控制流、函数、接口、字符串、并发、错误处理和泛型
题数：30
本批唯一 ID 前缀：go-syntax-20261005-b01

请仅根据以上四项参数生成题目；题数须为 1–5000 的整数，并严格输出指定数量的记录。本提示词是完整规范，不依赖特定仓库、文件路径或其他文档。只输出 JSONL 题目行，不输出说明、标题、Markdown 围栏或其他文字。每个物理行必须是一个完整 JSON 对象；不要外层数组。最终文件可使用 UTF-8 BOM、LF 或 CRLF，允许空行和末尾换行。不要把规范文档中的示例题照抄或复用为生成结果。

每个对象必须且只能包含以下字段：
- id：字符串，必须匹配 /^[a-zA-Z0-9][a-zA-Z0-9._:-]{0,99}$/。按“本批唯一 ID 前缀-序号”生成，从 001 开始递增；题目数超过 999 时继续自然扩展序号。整批 ID 不重复，且不要与已有题库或 30 道内置示例题的 ID 冲突。已有 ID 仅可用于标准化后内容完全相同的题目；任何内容改版都使用新 ID。重生成时，完全相同的题目保留原 ID 以便导入跳过；内容有变化就使用新的批次前缀，不得改写旧 ID。
- language：1–80 字符，使用语言/学科参数指定名称，不含版本号，例如 `Go`。
- topic：1–120 字符，写本题所属的简明主题，须落在以上主题范围内。
- stem：1–12000 字符，清晰给出题目和必要上下文；可在 JSON 字符串内使用 Markdown 及围栏代码块。
- options：对象必须恰好包含 A、B、C、D 四个键。每个值是 1–4000 字符的字符串；trim 去除前后空白后，四项内容必须互不相同。
- answer：只能是 "A"、"B"、"C"、"D" 之一，表示当前对象 options 中正确答案的原始键。
- explanation：1–12000 字符，说明为什么该答案正确，且必须与题干、四个选项和 answer 一致。
- duration_seconds：整数，范围 1–3600；普通语法题建议 45–120 秒。
- 可选 tags：字符串数组，最多 12 项，每项 1–50 字符。
- 可选 go_version：仅适用于 Go 题，值为 1–40 字符。若参数指定了 Go 版本，就填写该版本，例如 Go 1.25 填 `"go_version":"1.25"`；非 Go 题省略此字段。

根对象不得包含以上列表以外的字段。

一道题只能有一个明确、稳定的正确答案。题干、选项文字和解析不得依赖或提及 A/B/C/D 的位置，因为答题时选项会重新洗牌；不要使用“以上皆是”等依赖选项位置的写法。解析直接解释知识点，不要说“选项 B 正确”或引用文件中的答案字母。

代码题应注明必要的导入、代码所在上下文和影响结果的前提。核对目标语言版本和规则；不要依赖未规定的执行顺序、随机调度、系统环境或实现细节。若运行结果不确定，就改写题目或将不确定性本身作为考点。系统只校验数据结构，不会运行代码或证明答案正确；输出前请逐题核验题干、选项、唯一答案和解析。

题目数不得超过 5000 道非空题目行，输出文件不得超过 5 MB。题干或解析中的真实换行必须在 JSON 文本里写作两个字符 \n（反斜杠和 n）；解析 JSON 后它才成为换行。若用程序序列化，请把含真实换行的字符串交给 JSON.stringify，不要预先手动替换成字面量 \n，否则会双重转义。代码块可留在 stem 或 explanation 的字符串值内，但 JSONL 每道题仍必须占单一物理行。
```

使用时复制整个代码块，填好开头四项后交给外部 Agent；将 Agent 返回的原始 JSONL 保存为 `.jsonl` 文件并导入。
